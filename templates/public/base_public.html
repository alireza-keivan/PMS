{% load i18n i18n_extras static %} {% comment %} The visitor's shell, for the public mini villa sites at /villa///. Deliberately NOT extending base.html, for the same reason portal/base_portal.html doesn't: base.html always pulls in partials/_topnav.html, which reads `user`, `is_manager` and reverses staff-only URL names. A visitor here has no account and never signs in, so every one of those is absent or meaningless. It is not base_portal.html either, and the differences are the point: - Indexable. A guest link is private and carries `noindex`; this page exists to be found. So: a real description, Open Graph tags so a link pasted into WhatsApp or Instagram previews with the cover photo, and a canonical URL so the /id/ and unprefixed versions don't compete with each other in search. - Almost no JavaScript. Guests arrive on 4G on a phone, often mid-holiday. No HTMX and no Alpine: the photo strip is a CSS scroll-snap row, the dates are native date inputs, and the booking form is a plain POST. Nothing on this page needs a script to work, so nothing is loaded. - The language switcher stays. Plenty of guests are domestic, and Bahasa Indonesia matters more here than on any staff screen. {% endcomment %} {% block title %}{% endblock %} {% comment %} The same page is served at /villa/... and /id/villa/..., so each language points at itself as canonical and declares the other with hreflang. WhatsApp reads og:title/og:description/og:image; Instagram and Facebook read the same set. The image has to be an absolute URL - a relative one silently gets no preview. {% endcomment %} {% block og_image %}{% endblock %} {% block extra_head %}{% endblock %} {% comment %} No nav bar - there is nowhere else to go.
